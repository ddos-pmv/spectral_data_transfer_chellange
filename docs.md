# Оптимизация формата сообщений: разбор по полям

## Приёмы оптимизации

- **(D) дубль/производное** — поле выводится из других, информация не теряется.
- **(E) кодирование** — то же значение компактнее (строка→id, u32→u16, абсолют→дельта).
- **(M) merge в биты** — булевы флаги в один байт.
- **(P) паддинг** — байты, существовавшие только ради `alignas(64)`.

## Header

| Поле             | Было | Действие                        | Почему                                                                                                        |
|------------------|------|---------------------------------|---------------------------------------------------------------------------------------------------------------|
| `seq_id` u64     | 8    | оставил                         | Framing. Consumer детектит дропы по разрывам seq. Трогать нельзя.                                             |
| `send_ts_ns` u64 | 8    | оставил                         | Framing. По нему меряется латентность. Трогать нельзя.                                                        |
| `type` u16       | 2    | сузил → u8 (E)                  | Типов 3, влезает в 255.                                                                                       |
| `version` u16    | 2    | убрал                           | Версия формата — свойство сессии, согласуется на хэндшейке, а не в каждом сообщении.                          |
| `body_len` u32   | 4    | убрал                           | При фикс-размере на тип выводится из `type`. Длину на проводе несёт транспорт (в ринге уже есть `frame_len`). |
| —                | —    | добавил `instrument_id` u32 (E) | Общий для всех типов, вытесняет `symbol`+`venue`+валюты из каждого body.                                      |
| `reserved` u16   | —    | паддинг до 8-байта              | Неизбежные 2 байта после u32; отдал под future venue flags.                                                   |

Итог: 24→24 байта, но вместо `version`+`body_len` теперь несёт `instrument_id`+`type`+`flags`.

## Trade (192 → 56)

| Поле                     | Было | Действие                   | Почему                                                                                                                 |
|--------------------------|------|----------------------------|------------------------------------------------------------------------------------------------------------------------|
| `symbol[16]`             | 16   | убрал (E)                  | В hot path гоняют числовой `instrument_id`, а не ASCII. Словарь id→symbol — на старте сессии.                          |
| `venue[16]`              | 16   | убрал (E)                  | То же — часть `instrument_id`/словаря.                                                                                 |
| `base_currency[8]`       | 8    | убрал (D)                  | Выводится из инструмента (BTCUSDT → base BTC).                                                                         |
| `quote_currency[8]`      | 8    | убрал (D)                  | То же (→ USDT).                                                                                                        |
| `trade_id` u64           | 8    | оставил                    | Биржевой id сделки, реальная инфа, из `seq_id` не выводится.                                                           |
| `exchange_ts_ns` u64     | 8    | сузил → int32 дельта (E)   | Абсолютные ns — 8 байт, где верхние почти константны. Полезен зазор «биржа матчнула → мы отправили». int32 ns = ±2.1с. |
| `match_engine_ts_ns` u64 | 8    | убрал (D)                  | В продюсере буквально `= exchange_ts_ns`. Дубль.                                                                       |
| `price` double           | 8    | убрал (D)                  | Дубль `price_ticks`.                                                                                                   |
| `quantity` double        | 8    | убрал (D)                  | Дубль `quantity_lots`.                                                                                                 |
| `notional` double        | 8    | убрал (D)                  | = `price × quantity`. Чистая производная.                                                                              |
| `price_ticks` i64        | 8    | оставил                    | Теперь ЭТО цена. Целые тики: точно, детерминированно, быстрое сравнение — HFT-стандарт.                                |
| `quantity_lots` i64      | 8    | оставил                    | Теперь ЭТО объём.                                                                                                      |
| `tick_direction` u32     | 4    | merge → flags биты 4-5 (M) | Значения 0..3 = 2 бита. Держать под это 4 байта — абсурд.                                                              |
| `aggressor_side` u8      | 1    | merge → flags бит 0 (M)    | 1 бит.                                                                                                                 |
| `is_block_trade` u8      | 1    | merge → flags бит 1 (M)    | 1 бит.                                                                                                                 |
| `is_rpi` u8              | 1    | merge → flags бит 2 (M)    | 1 бит.                                                                                                                 |
| `is_liquidation` u8      | 1    | merge → flags бит 3 (M)    | 1 бит.                                                                                                                 |
|                          | 1    | `flags` u8 добавил         | Тот самый байт, куда всё слилось.                                                                                      |
| `reserved[19]`           | 19   | убрал (P)                  | Существовал только чтобы добить структуру до 192 под `alignas(64)`.                                                    |

В этом не уверен.
Плюс снят `alignas(64)` с самой структуры — выравнивание кэш-линии это забота `Slot` в ринге, на проводе не нужно. Хвостовой `reserved u32` — естественный паддинг до 8-байтной границы (56, а не 52).

## Level (40 → 16)

Повторяется 10 раз (5 bid + 5 ask), поэтому экономия умножается ×10 — главный источник ужатия книги.

| Поле              | Было | Действие        | Почему                         |
|-------------------|------|-----------------|--------------------------------|
| `price` double    | 8    | убрал (D)       | Дубль `price_ticks`.           |
| `size` double     | 8    | убрал (D)       | Дубль `size_lots`.             |
| `price_ticks` i64 | 8    | оставил         | Цена уровня.                   |
| `size_lots` i64   | 8    | сузил → i32 (E) | Объём уровня в i32 влезает.    |
| `order_count` u32 | 4    | сузил → u16 (E) | ≤65k.                          |
| `reserved` u32    | 4    | → u16 pad (P)   | Осталось 2 байта выравнивания. |

## Принцип одной фразой

Из каждой сущности убрано ровно одно — **избыточность**. Дубли представления (double + ticks), дубли таймстемпов, выводимые поля (notional, валюты), широкие типы под узкие значения, и паддинг — артефакт кэш-выравнивания, не имеющего смысла на проводе. Ни одного поля не выброшено «на глаз»: под каждым либо (D), либо (E), либо (M), либо (P).
